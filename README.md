# GF-2 土地覆盖分类实战工具包

用一景 0.8 米四波段 GF-2 影像 + Prithvi-EO-2.0，训练出 6 类土地覆盖分类模型。

## 前置条件（没做完先回去补）

1. 按学习指南第 5 章装好 `prithvi` 环境（Miniconda + TerraTorch）
2. 按第 6 章跑通官方滑坡检测示例——环境和流程验证过，后面出问题才好定位
3. 本目录所有命令都在 `prithvi` 环境里运行：先 `conda activate prithvi`，再 `cd` 到本目录

## 文件清单

| 文件 | 作用 | 什么时候用 |
|---|---|---|
| `01_check_bands.py` | 检查影像波段数、分辨率 | 第 1 步 |
| `02_tile.py` | 切成 224×224 训练块 + 自动划分训练/验证 | 第 3 步 |
| `03_train.py` | 训练脚本（自动读取切片统计） | 第 4 步 |
| `04_predict_scene.py` | 整幅推理，输出分类图 | 第 5 步 |

## 类别方案

| 编号 | 类别 | 判读要点（0.8 米下） |
|---|---|---|
| 0 | 未标注 | 不画就是 0，训练时自动忽略 |
| 1 | 耕地 | 规则田块纹理，田埂清晰可见 |
| 2 | 林地 | 深绿成片、边缘不规则，可见树冠颗粒感 |
| 3 | 草地 | 浅绿均匀，无树冠颗粒，不成田块 |
| 4 | 水域 | 蓝/深蓝/黑色，色调均匀，边界清晰 |
| 5 | 建设用地 | 灰白色建筑、道路，几何形状规则 |
| 6 | 未利用地 | 裸土、沙地、撂荒地，土黄或灰褐色 |

拿不准的地块宁可不标（留 0），错标比漏标伤害更大。

## 第 0 步 · 先裁一块试验区（强烈建议）

一景完整 GF-2 融合影像动辄数万像素见方，全部标注要画几天。第一次做，建议在 QGIS 里裁出
一块 5000×5000 像素左右（约 4×4 公里）的典型区域来练手：

> QGIS 菜单：栅格 → 提取 → 按范围裁剪，画框选区后导出，得到 `study_area.tif`。
> 后面 01/02/04 脚本都对着这块试验区做，跑通后再扩大范围。

## 第 1 步 · 检查影像

```
python 01_check_bands.py study_area.tif
```

确认输出为「4 波段数据」。只有 3 波段说明拿到的是 RGB 可视化产品，缺近红外，需要找供应商要原始 MSS+PAN 数据。

## 第 2 步 · QGIS 标注（全流程最花时间的一步，约半天）

1. **新建面图层**：图层菜单 → 创建图层 → 新建 Shapefile 图层 → 几何类型选「多边形」，
   坐标系选和影像一致，添加一个整数字段 `class`，保存为 `labels.shp`
2. **画多边形**：选中 `labels.shp` 开始编辑，沿地物边界画多边形，在 `class` 字段里填类别编号
   （对照上面的类别表）。画完一块保存一块，画错可以删除重画
3. **数量目标**：每类至少 50 个多边形，稀少的类（如未利用地）至少 20 个，
   尽量散布在试验区各处，不要只集中在一角
4. **导出标签栅格**（关键步骤，参数错后面全错）：处理工具箱 → 搜索「栅格化（矢量到栅格）」，
   参数这样填：
   - 输入图层：`labels.shp`，字段：`class`
   - 输出像元大小：填 `01_check_bands.py` 打印的分辨率数值（如 0.8）
   - 输出范围：点旁边的按钮选「使用图层范围」→ **选影像图层**（不是 labels.shp！）
   - 初始值：`0`（没画到的地方自动是 0=未标注）
   - 输出数据类型：`Byte`
   - 保存为 `label.tif`
5. **对齐检查**：把 `label.tif` 加进 QGIS 叠在影像上，类别色块应该正好盖住对应地物。错位说明第 4 步范围或像元大小填错了

## 第 3 步 · 切片

```
python 02_tile.py study_area.tif label.tif
```

产出几千个训练块到 `data/tiles/`，并统计各波段均值/标准差存进 `data/stats.json`（训练脚本自动读取，无需手动填写）。

## 第 4 步 · 训练

```
python 03_train.py
```

脚本会自动读取 `data/stats.json`，参数已按 8GB 显存调好。默认 40 轮 + 早停（验证 loss 连续
10 轮不降自动停），视标注量约 1–3 小时。日志里 loss 持续下降、验证指标逐步上升就是正常。

训练产物：`output/checkpoints/best.ckpt`（最佳模型）。想调参数就打开 `03_train.py`，
顶部的 `BATCH_SIZE` / `MAX_EPOCHS` 等常量都有中文注释。

## 第 5 步 · 整幅出图

```
python 04_predict_scene.py study_area.tif output\checkpoints\best.ckpt result.tif
```

得到 `result.tif`（类别编号）和 `result_color.tif`（配色图）。配色图直接拖进 QGIS，
和影像叠加对比，看哪些类别分得好、哪些混淆。

## 结果怎么算正常

- 6 类土地覆盖在几百个训练块上，验证集 mIoU（平均交并比）到 0.6–0.8 属于正常水平
- 常见混淆：草地↔未利用地、建设用地↔裸土。把混淆区域补标几块，重跑第 2-5 步，通常一轮就能明显改善

## 常见错误速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 验证阶段报 `bincount ... non-negative` | 标签 tif 带 nodata 声明，训练框架读取时对应像素变 NaN，转整数成巨大负数 | 已修复：`03_train.py` 内置 `no_label_replace=0`；跑 `check_labels.py` 可确认诊断 |
| 验证阶段报 `preds must be (N,C,H,W) or (N,H,W)` | TerraTorch 1.2.11 自带 Boundary_mIoU 指标的形状 bug | 已修复：`03_train.py` 训练前自动移除该指标 |
| `CUDA out of memory` | 显存不足 | 打开 `03_train.py` 把 `BATCH_SIZE` 改 2；还不行把 `DECODER_CHANNELS` 改 64 |
| 数据加载卡死不动 | Windows 多进程问题 | `03_train.py` 里 `num_workers` 保持 0 |
| 切片报尺寸不一致 | 标签栅格化时范围/像元不对 | 重做第 2 步第 4 小步 |
| 训练块数量为 0 | 标签大面积没画或没对齐 | 检查 `label.tif` 叠加显示 |
| 训练前报找不到 stats.json | 没跑切片就训练 | 先运行 `02_tile.py` |

## 数据体检

任何时候怀疑数据有问题，一键检查切片标签（数值范围 / 类型 / 形状 / 是否会触发 NaN）：

```
python check_labels.py
```

## 诚实提醒

`03_train.py` 与已跑通的官方滑坡示例（`prithvi-example/run_train.py`）使用同一套 Python 接口，
仅波段数（4 波段 GF-2）、类别数（6 类 + 忽略未标注）不同。若报错，把原文发我。
其余三个脚本只依赖 rasterio/numpy/torch，都是 prithvi 环境自带。
